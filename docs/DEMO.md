# Как показать и записать BankTrap

[Готовая запись демо — MP4, 1:20](demo.mp4). Видео без озвучки, с русскими субтитрами; при необходимости включите их в плеере.

## Подготовка — 5 минут

1. Запустите `python3 app.py` из папки `mvp`, откройте `http://127.0.0.1:8765`.
2. Раскройте «Доступ оператора», вставьте токен из терминала и нажмите «Подключить SOC». Токен не показывайте крупным планом в видео.
3. Нажмите «Сбросить демо». Разверните браузер; масштаб 80–90% при необходимости. Для записи достаточно 1920×1080, 30 fps.
4. Отключите уведомления. Записывайте только окно браузера с вымышленными данными. Интернет для приложения не нужен.
5. Один раз пройдите сценарий ниже; перед записью снова сбросьте демо.

## Сценарий видео — около 3 минут

**0:00–0:20 — проблема.** Покажите обложку презентации или заголовок приложения. Текст: «BankTrap помогает банковскому SOC пройти от наблюдения за атакой до проверенного кандидата правила. Сейчас покажем локальный прототип на синтетических данных».

**0:20–0:35 — запрос без правила.** В блоке «Шлюз» нажмите «Повторить SQLi». Ожидается HTTP 200, «ПРОПУЩЕНО». Текст: «В тестовом шлюзе правило выключено; запрос проходит. Шлюз не исполняет банковскую операцию». Важно: это шлюз с отключённым правилом, а не действующий WAF банка.

**0:35–1:00 — событие.** В «ДемоБанке» нажмите «Подставить SQLi», затем «Войти». Покажите имитированный вход и событие «Попытка SQLi» в ленте. Текст: «Приманка имитирует успех, сохраняет пример и контекст. Произвольный SQL не выполняется; пароль в журнал не попадает».

**1:00–1:25 — кандидат.** Нажмите «Создать кандидат». Раскройте «Посмотреть JSON» и покажите идентификатор, версию, ссылку на событие и формат `banktrap-demo/v1`. Текст: «Из библиотеки шаблонов выбран кандидат. Для банковского внедрения нужен адаптер конкретного WAF; в рабочую защиту банка он автоматически не отправляется».

**1:25–1:55 — качество.** Нажмите «Проверить на наборе». Ожидается TP 8, FN 0, FP 0, TN 12. Текст: «Проверили восемь атак и двенадцать обычных запросов. Это результат на открытом демонстрационном наборе. Ниже указаны известные пропуски и возможное ложное срабатывание. Для пилота потребуется отдельный набор банка».

**1:55–2:20 — изменение поведения.** Нажмите «Включить проверенный кандидат», затем «Повторить SQLi»: HTTP 403. Нажмите «Обычный запрос»: HTTP 200 для `o'reilly`. Текст: «Тот же атакующий запрос теперь блокируется, обычный проходит».

**2:20–2:40 — передача результата и откат.** Нажмите «Скачать отчёт». Затем «Откатить» и «Повторить SQLi»: снова HTTP 200. Текст: «Отчёт содержит событие, версию правила и результаты проверки. Изменение можно отменить».

**2:40–3:00 — ценность и запрос.** Покажите слайд с пилотом. Текст: «Следующий шаг — два тестовых сервиса банка и сравнительный пилот. Проверим гипотезу сокращения активного времени аналитика на 30% без ухудшения качества. Это целевой результат, а не уже достигнутая экономия».

Дополнительные функции показывайте только если есть время: учётка-приманка → вход → T1078; пять неудачных входов → T1110.001; открытая админка → событие без ошибочной метки T1078; имитация перевода после входа. Генератор правил в этой версии предназначен только для SQLi.

## Запись на macOS

Нажмите Shift+Cmd+5, выберите запись выделенной области, обведите браузер. В параметрах выберите микрофон и место сохранения, затем «Записать». Остановите через кнопку в строке меню. Прослушайте начало и конец, убедитесь, что в кадр не попали личные уведомления или терминал с другими проектами. Сохраните как `BankTrap-demo.mov` или экспортируйте MP4 доступным редактором.

Официальная инструкция: [запись экрана на Mac, Apple](https://support.apple.com/ru-ru/102618).

На Windows можно использовать установленное средство записи экрана или OBS: источник «Захват окна», окно браузера, микрофон, 1080p/30 fps. На любом устройстве сначала сделайте 10-секундную пробу звука. Для совместимости площадки демонстрации уточните допустимый формат и лимит размера файла.

## Если что-то пошло не так

- «Введите токен» — возьмите актуальный токен из запущенного сервера: после перезапуска он меняется.
- «Сначала отправьте SQLi» — недостаточно нажать «Подставить SQLi», нужно ещё «Войти».
- «Нужна успешная проверка» — создайте кандидат и выполните повторную проверку перед включением.
- Перевод отклонён — сначала войдите; не используйте его как обязательный этап основного демо.
- Порт занят — запустите с `--port 8766` и откройте этот порт.
- Для терминального дубля используйте `python3 demo.py`; браузерная лента покажет его события.
- Если запись сорвалась, сбросьте демо и начните заново. Не монтируйте неуспешный результат так, будто функция сработала.

## Короткий питч без демонстрации

Для защиты на 5 минут используйте слайды 1, 3, 4, 7, 9, 11, 14 и 18. Остальные — подробности для вопросов. Если к защите добавляется трёхминутное видео, отведите на рассказ ещё 3–5 минут. В PowerPoint включите режим докладчика: заметки содержат ограничения цифр и полные ссылки.

«BankTrap — стенд для проверки защитных правил. Аналитик получает событие с банковской приманки, готовит правило и проверяет его на атакующих и обычных запросах. В прототипе можно включить правило в тестовом шлюзе, повторить запрос и выполнить откат. Следующий шаг — подключить WAF банка и сравнить время работы с текущим процессом. Для пилота нужны два тестовых сервиса, инженер WAF, аналитик SOC и обезличенные примеры задач. За 4–6 недель оценим время, качество правил и затраты на сопровождение. Цель — сократить время подготовки правила на 30% без ухудшения качества».
